# TaskTree 기반 풀스택 학습 기준

## 목적

풀스택 코딩테스트 문제를 만들 때 포트폴리오 프로젝트인 TaskTree에서 사용한
기술과 실무 관점을 참고한다.

TaskTree의 코드를 그대로 복사하거나 전체 구조를 한 번에 분석하는 것이
목표는 아니다. 작은 문제를 직접 풀고 리뷰하면서 AI가 작성한 코드를 읽고
검증할 수 있는 힘을 기르는 것이 목표다.

## 우선 학습 역량

### 1. 작은 함수 검증

- 배열과 객체 변환
- null과 빈 값 처리
- 중복 제거와 정렬
- 원본 입력값 변경 여부
- 시간 복잡도와 공간 복잡도

### 2. 프론트엔드 코드 리뷰

- loading, empty, error 상태 분리
- 부분 실패 처리
- 불안정한 `useEffect` 의존성
- 중복 API 호출
- 사용자 입력 정규화
- 서버 권한 검증과 UI 표시 제어의 차이

### 3. API 코드 리뷰

- 요청값 검증
- 클라이언트가 보낸 사용자 ID나 소유자 ID를 그대로 신뢰하는 문제
- 인증과 인가의 차이
- 읽기 권한과 쓰기 권한의 차이
- 일관된 오류 응답
- 실패를 숨기는 `catch` 블록

### 4. 데이터 접근 리뷰

- 필요한 조회 조건을 먼저 정의하기
- 전체 조회와 불필요한 반복 조회 찾기
- 중복 결과와 누락 결과 찾기
- DynamoDB 인덱스가 필요한 상황 판단
- SQL 문제에서는 JOIN, 집계, NULL 처리로 같은 사고방식 연습

### 5. 패키지 책임 경계

TaskTree의 구조를 일반화하여 다음을 판단하는 문제를 만든다.

- UI 코드가 서버 전용 SDK를 직접 호출하지 않는가
- 공통 타입과 API 계약이 적절한 계층에 있는가
- 서버 로직이 UI 상태를 처리하지 않는가
- 인프라 설정과 비즈니스 로직이 섞이지 않았는가
- 공통 UI 컴포넌트가 도메인 로직을 과도하게 가지지 않는가

### 6. 인프라 변경 리뷰

- 새로운 API 경로가 필요한가
- 새로운 Lambda가 필요한가
- 데이터베이스 인덱스 변경이 필요한가
- IAM 권한이 과도하게 넓어지지 않는가
- 배포 영향이 있는가

인프라 문제는 구현 암기보다 변경 영향 설명과 위험 발견을 우선한다.

## 문제 구성 방식

Claude Code는 풀스택 트랙의 문제를 다음 네 가지 유형으로 섞어서 만든다.

| 유형 | 설명 |
| --- | --- |
| 직접 구현 | 작은 함수, API 로직, 데이터 변환을 직접 작성 |
| 버그 수정 | 의도적으로 잘못된 코드의 원인과 수정 방향 분석 |
| 코드 리뷰 | 변경 코드에서 보안, 권한, 상태 처리, 책임 경계 문제 찾기 |
| 테스트 작성 | 빠진 공개 테스트 또는 엣지 케이스 작성 |

초기에는 한 문제에서 하나의 주요 결함만 다룬다. 익숙해지면 서로 연관된
두세 가지 결함을 포함한 실무형 문제로 확장한다.

## 난이도 조절

### 초급

- 한 파일 안에서 동작하는 작은 함수
- 명확한 실패 입력이 있는 버그
- 공개 테스트로 계약을 이해할 수 있는 문제

### 중급

- UI, 공통 타입, API 중 두 계층을 연결하는 문제
- 비동기 실패 처리
- 권한 검증 누락
- 테스트 추가가 필요한 문제

### 고급

- 여러 계층의 변경 영향 분석
- 테넌트 분리와 리소스 권한 검토
- 데이터 접근 패턴과 인프라 영향 판단
- E2E 관점의 재현 절차 설계

처음부터 고급 문제만 출제하지 않는다. `docs/mistakes.md`와 사용자의 리뷰
결과를 보고 단계적으로 올린다.

## 문제 출제 시 주의 사항

- TaskTree의 소스 코드를 그대로 복제하지 않는다.
- 포트폴리오의 비밀 설정, 토큰, 개인정보를 문제에 포함하지 않는다.
- 특정 기업의 실제 기출이라고 단정하지 않는다.
- 구현 문제만 만들지 않고 코드 리뷰와 테스트 작성 문제를 포함한다.
- 정답 암기보다 오류 원인 설명과 재현 절차 작성을 요구한다.
