# Claude Code 문제집 생성 프롬프트

새로운 문제 세트를 만들 때 아래 프롬프트의 대괄호 항목을 채워서 Claude
Code에게 전달한다.

```text
당신은 이 저장소의 코딩테스트 문제 출제 담당자입니다.

먼저 다음 파일을 읽으세요.
- AGENTS.md
- CLAUDE.md
- docs/study-plan.md
- docs/progress.md
- docs/mistakes.md

직무가 fullstack이면 다음 파일도 읽으세요.
- docs/fullstack-tasktree-baseline.md

다음 조건으로 문제 세트를 만드세요.
- 언어: [typescript 또는 python]
- 직무: [frontend, backend, fullstack 중 하나]
- 목표 채용 플랫폼 또는 공개 문제 유형: [직접 입력]
- 현재 단계: [입문, 기초, 중급, 실전, 모의 테스트 중 하나]
- 문제 수: [입문 단계의 기본값은 1~2문제]
- 집중 주제: [직접 입력하거나 오답 기록을 바탕으로 선택]

직무가 fullstack이면 직접 구현, 버그 수정, 코드 리뷰, 테스트 작성 문제를
섞으세요. TaskTree의 소스 코드를 그대로 복제하지 말고 기술과 리뷰 관점을
일반화하세요. 초기 문제는 작은 범위에서 하나의 주요 결함을 다루세요.

처음부터 8~12문제를 만들지 마세요. AGENTS.md의 문제 수 조절 기준을
따르세요. 초기에는 1~2문제를 제시하고 상세 리뷰가 끝난 뒤 다음 문제 수를
결정하세요.

특정 기업이나 채용 플랫폼을 참고한다면 공개적으로 확인 가능한 시험 유형만
사용하세요. 확인할 수 없는 기업 기출 문제라고 단정하지 마세요. 문제 원문을
복제하지 말고 학습 목적에 맞게 변형하세요.

파일을 작성하기 전에 다음 내용을 먼저 제시하세요.
1. 그날의 학습 목표
2. 명시적인 요구사항으로 정리해야 할 전제 조건
3. 분야, 난이도, 예상 풀이 시간을 포함한 문제 목록
4. 새로운 실행 환경 의존성이나 이례적으로 어려운 주제를 추가하는지 여부

사용자의 지시를 받은 뒤 공개 파일을 만드세요.
- exercises/{language}/{role}/day-NN/NN-slug/README.md
- exercises/{language}/{role}/day-NN/NN-slug/starter.ts 또는 starter.py
- exercises/{language}/{role}/day-NN/NN-slug/public.test.ts 또는 test_public.py

출제자 전용 파일은 분리하여 만드세요.
- .authoring/solutions/reference/{language}/{role}/day-NN/NN-slug/solution.ts 또는 solution.py
- .authoring/explanations/{language}/{role}/day-NN/NN-slug/README.md
- .authoring/hidden-tests/{language}/{role}/day-NN/NN-slug/hidden.test.ts 또는 test_hidden.py

각 문제의 README.md에는 다음 내용을 포함하세요.
- 언어
- 직무
- 난이도
- 예상 풀이 시간
- 대비 유형
- 참고 범위
- 학습 목표
- 요구사항
- 명시적인 전제 조건
- 예시
- 제약 조건
- 완료 조건
- 시간 복잡도와 공간 복잡도를 설명하기 위한 질문

규칙:
- solutions/user/를 수정하지 마세요.
- 시작 코드나 공개 테스트를 통해 정답을 노출하지 마세요.
- 각 문제는 하나의 주요 학습 목표에 집중하세요.
- 단순한 구현을 우선하고 불필요한 추상화를 추가하지 마세요.
- 의미 있는 숨겨진 엣지 케이스를 포함하세요.
- 기존 오답을 바탕으로 변형 문제를 만들되 같은 문제를 반복하지 마세요.
- 실행하지 못한 검증 명령과 실패한 테스트를 모두 보고하세요.

출제가 끝나면 다음 절차를 따르세요.
1. 가능한 type-check, lint, test 명령을 실행하세요.
2. 생성한 파일을 요약하세요.
3. 실패를 숨기지 않고 검증 결과를 요약하세요.
4. Codex에게 요구사항의 모호함, 테스트 범위, 정답 코드, 난이도, 중복 여부를
   독립적으로 검토하도록 요청하세요.
```

## 사용자 풀이 리뷰 요청 프롬프트

풀이가 끝난 뒤 아래 프롬프트를 Claude Code에게 전달한다.

```text
사용자가 solutions/user/ 아래에 작성한 풀이를 리뷰하세요.
사용자 풀이 파일을 직접 수정하지 마세요.

공개 테스트와 숨겨진 테스트를 실행하고 다음 순서로 상세히 분석하세요.
1. 정답 여부
2. 누락된 요구사항
3. 실패하는 입력 예시
4. 엣지 케이스
5. 언어별 타입 또는 런타임 안전성
6. 원본 배열, 객체, 리스트, 딕셔너리 변경 여부
7. 시간 복잡도와 공간 복잡도
8. 가독성
9. 테스트 부족
10. 오류 원인
11. 개선 방향
12. 다음에 풀 변형 문제 또는 보완 학습 주제

정답 전체 코드는 사용자가 명시적으로 요청한 경우에만 공개하세요.
실패한 테스트를 숨기지 마세요.
문제 오류와 사용자 풀이 오류를 구분하세요.
리뷰가 끝나면 docs/mistakes.md와 docs/progress.md를 갱신하세요.
최근 풀이 결과를 바탕으로 다음 문제 수를 유지할지, 줄일지, 늘릴지 근거와
함께 제안하세요.
마지막으로 Codex에게 리뷰 결과의 누락과 오류를 검토하도록 요청하세요.
```
