# 4주 학습 계획

## 목표

프론트엔드, 백엔드, 풀스택 엔지니어 이직 과정의 코딩테스트를 대비한다.
TypeScript와 Python은 별도 트랙으로 관리한다. 같은 주제를 다루더라도
언어와 직무에 따라 문제 형태와 평가 기준을 다르게 구성한다.

## 학습 단위

Claude Code에게 문제 생성을 요청할 때 다음 항목을 지정한다.

| 항목 | 예시 |
| --- | --- |
| 언어 | `typescript`, `python` |
| 직무 | `frontend`, `backend`, `fullstack` |
| 목표 채용 플랫폼 또는 공개 문제 유형 | 기업 코딩테스트, 알고리즘 플랫폼, 실무 과제형 |
| 한 번에 제시할 문제 수 | 입문 1~2문제, 숙련도에 따라 점진적으로 증가 |
| 집중 주제 | 오답 기록 또는 지원 직무에 따라 지정 |

하루에 모든 트랙을 동시에 풀 필요는 없다. 하나의 언어와 직무 트랙을
선택하여 집중한다. 처음에는 1~2문제를 풀고 리뷰를 마친 뒤 다음 문제를
결정한다. 8~12문제는 초기 목표가 아니라 모의 테스트 단계의 목표다.

## 언어별 기본 방향

### TypeScript

- 배열과 객체 데이터 가공
- 타입 좁히기, null 처리, 불변성
- 함수 구현과 기본 알고리즘
- async/await와 오류 처리
- 테스트 코드 작성
- REST API 입력 검증
- SQL

프론트엔드 트랙은 상태 갱신, 응답 데이터 변환, 테스트를 강화한다.
백엔드 트랙은 API 로직, 오류 처리, SQL을 강화한다.
풀스택 트랙은 두 영역을 연결하는 실무형 문제를 포함한다.
풀스택 트랙의 상세 기준은 `docs/fullstack-tasktree-baseline.md`를 참고한다.

### Python

- 문자열, 리스트, 딕셔너리, 집합
- 정렬, 탐색, 스택, 큐, 힙
- 그래프, 완전 탐색, 동적 계획법
- 데이터 처리와 성능 개선
- 테스트 작성
- 백엔드 로직과 SQL

Python 프론트엔드 트랙은 알고리즘 평가 대비를 중심으로 구성한다.
Python 백엔드 트랙은 알고리즘과 데이터 처리, SQL 비중을 높인다.
Python 풀스택 트랙은 알고리즘과 웹 서비스 로직을 함께 다룬다.

## 1주차: 기본기 진단

- 언어별 기본 문법과 자료구조
- 데이터 가공
- 타입 또는 런타임 오류
- 입력값 변경 여부
- 시간 복잡도 설명
- SQL 기초

목표: 현재 강점과 약점을 찾고 `docs/mistakes.md`에 기록한다.

풀스택 트랙에서는 작은 구현 문제와 함께 한 파일 단위의 코드 리뷰 문제를
포함한다. 처음부터 포트폴리오 전체를 분석하지 않는다.

문제 수: 한 번에 1~2문제

## 2주차: 빈출 패턴과 오류 처리

- 정렬, 탐색, 스택, 큐, 해시 기반 문제
- 여러 단계의 데이터 변환
- 비동기 처리와 실패 경로
- 테스트 케이스 작성
- SQL JOIN과 집계

목표: 자주 쓰는 풀이 패턴을 설명하고 직접 적용한다.

문제 수: 최근 리뷰 결과에 따라 한 번에 2~3문제

## 3주차: 직무별 실전 문제

- 프론트엔드: 상태 처리, 데이터 변환, 테스트, 코드 리뷰
- 백엔드: API 로직, 유효성 검증, 오류 처리, SQL
- 풀스택: 화면과 API 사이의 계약, 데이터 흐름, 버그 분석
- Python 알고리즘 평가: 그래프, 완전 탐색, 동적 계획법

목표: 지원 직무에 가까운 문제를 제한 시간 안에 해결한다.

문제 수: 최근 리뷰 결과에 따라 한 번에 3~5문제

## 4주차: 모의 코딩테스트와 약점 보완

- 목표 채용 플랫폼 유형에 맞춘 혼합 세트
- `docs/mistakes.md` 기반 변형 문제
- 시간제한 풀이
- 풀이 설명 연습
- AI 상세 리뷰를 통한 반복 실수 점검

목표: 정답을 보지 않고 풀이, 복잡도, 엣지 케이스를 설명한다.

문제 수: 6~8문제 혼합 세트부터 시작하여 준비가 되었을 때 8~12문제 모의
테스트로 확장

## 하루 학습 흐름

1. 사용자가 언어, 직무, 목표 유형을 정하여 Claude Code에게 문제 생성을
   지시한다.
2. Claude Code가 문제와 출제자 전용 자료를 만든다.
3. Codex가 요구사항, 테스트, 정답, 중복, 난이도를 검토한다.
4. 사용자가 `solutions/user/` 아래에서 문제를 직접 푼다.
5. Claude Code가 풀이 리뷰 초안을 작성한다.
6. Codex가 리뷰 결과를 다시 검토하고 보완한다.
7. 사용자에게 오류 원인, 실패 입력, 복잡도, 개선 방향, 다음 학습 주제를
   상세히 설명한다.
8. 오답을 기록하고 다음 문제 세트의 주제와 문제 수를 조절한다.
